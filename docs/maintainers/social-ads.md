# Social & Ads (MericSEO)

Social Studio (`/p/:id/social`) and Ad Studio (`/p/:id/ads`) plan, generate and publish Instagram/Facebook posts and Meta ads from a project's own data. Generation happens in the user's Claude session through MCP; MericSEO stores context, drafts, media and the publishing state.

## Decisions

- **One context layer.** `SocialContextService` gathers brand kit + project context, saved and rank-tracked keywords, Search Console top/rising queries and pages, GA4 landing pages and items, the Shopify catalog and menu (or a sitemap crawl without Shopify), blog drafts and tracked pages, past social posts, competitors, AI visibility prompts, the competitor ad report and our ad drafts. It reads stored data and free APIs only (no DataForSEO calls), lists what is missing instead of failing, and is cached in KV for 24 hours (manual rebuild in the UI, `refresh` in `get_social_context`). Writes that change it invalidate the cache.
- **Brand kit lives next to project context**, not as a separate brand system: one row per project, edited on the Context page and printed by `get_project_context`. Tone and audience complement the existing context sections.
- **Meta connection per project**, like Shopify: Page ID, Instagram account ID, ad account ID and a System User token sealed with the Better Auth secret. The app stays in Development mode; no App Review.
- **Public media** is stored in R2 under `social/` and served by `/social-media/*`, which is exempt from Cloudflare Access so Meta can fetch it. PNG is converted to JPEG (Instagram accepts JPEG only); WebP is rejected; Shopify CDN images are requested as JPEG. Imports from URLs go through the SSRF-checked fetch with manual redirects.
- **Publishing** runs in the 5-minute cron for both Instagram and Facebook instead of Facebook's own `scheduled_publish_time`, so one status flow (draft → approved → scheduled → publishing → published / failed) covers both. Instagram's daily publishing quota is checked first; when it is used up the post stays scheduled and retries. Posts stuck in `publishing` for 20 minutes are marked failed with a "check before retrying" message to avoid duplicates. Story link stickers cannot be set through the API, so the tracked URL is stored for manual use.
- **Approval is user-only.** MCP tools create and edit drafts and set times; only the UI approves. Editing an approved post sends it back to draft.
- **Links** are verified against the live site (same host, loads with 200, no off-site redirect) and get UTM tags: `utm_medium=social` for posts, `paid_social` for ads, `utm_campaign=post-<id>` / `ad-<id>`.
- **Image text layer** is rendered in the browser (canvas) with brand colors, heading font and logo, so it costs nothing. Higgsfield (reframe/outpaint for 9:16, image or UGC video generation, video analysis) is run by Claude through the Higgsfield connector after the user confirms the credit cost; results are stored with `save_social_media`.
- **Competitor ads.** Meta's Graph `ads_archive` only returns commercial ads delivered in the EU/UK. A coverage test on 2026-10-29 showed Meta's official Ads connector (`ads_library_search`, free, uses the user's ad account) returns US and TR commercial ads, filterable by page ID, but without body text or media. It was chosen over paid scrapers (Apify) and over scraping the Ad Library site: zero cost, official access. Claude pulls ads with it and saves them with `save_competitor_ads`; body text, video URLs, transcripts and scene summaries are added when available. Ads running 30+ days carry the winner flag.
- **Ads go to Meta PAUSED only.** `MetaAdsPublisher` creates (or reuses) a PAUSED traffic campaign, a PAUSED dynamic-creative ad set with a small default daily budget, an asset-feed creative with all copy variations, and a PAUSED ad. There is no code path that sets ACTIVE. Created ids are saved step by step so a retry continues where it failed.

## Next step (not built)

Performance feedback loop: pull insights for our published posts (Instagram/Facebook) and our ads (by `meta_ad_id`, per asset-feed body/title) on a daily cron, store them per post/ad, and add them to the context layer's "Performance" section so generation can see which angles, hooks and formats won.
